\section{Reproducibility}\label{sec:repro}

Every table and macro, and the numbers of the tables' captions, are generated by \code{scripts/build\_data.py} from \code{data/runs.csv} (one row per measured run: command, counts, hardware, backend, and the
revisions of the three repositories) and \code{data/claims.csv} (the status of each claim and the run that supports it), and from the run reports in \code{data/runs/}.
The script refuses a claim marked met or partial whose evidence is not a run in that table, a run whose file is missing, and a run whose report disagrees with the count in its row. \code{make} builds the PDF.

The runs are made with the \code{voice-loop} sample of the repository (the commands are in the \code{command} column of \code{data/runs.csv}), for example
\begin{small}
\begin{verbatim}
voice-loop --backend cuda teach-eval --base Qwen3-8B \
    --scenarios data/teaching/scenarios-test.jsonl --report teaching-test.json
voice-loop --backend cuda teach-read --base Qwen3-8B \
    --utterances data/teaching/utterances.jsonl --report teaching-read.json
\end{verbatim}
\end{small}
The scenario and utterance sets are in \code{data/teaching}, written by \code{scripts/teaching\_set.py} and \code{scripts/teaching\_utterances.py}, with their digests; the pre-registrations are in \code{prereg/}. Models are fetched with \code{brain pull} (Qwen3-8B, Qwen3-TTS-12Hz-0.6B-Base, nemotron-3.5-asr-streaming-0.6b).
The spoken-conversation scripts, the sentence sets of the speech runs and the recorded audio live in the repository's speech resources, not in this directory; the stored run reports in \code{data/runs} hold everything the tables are built from. Where a run's row names a working tree, the source was committed immediately after, in the commit that adds the run.
