\section{Reproducibility}\label{sec:repro}

\paragraph{Data and models.}
The corpora are public-domain texts fetched by a checksummed script in the repository
(Washington, Randolph and Library editions of Jefferson's letters, his works, and an Adams
collection). The policy is Qwen3-8B (\code{BRAIN\_QWEN\_WEIGHTS} names the checkpoint, and
\code{SPLINTER\_BF16\_BASE=1} keeps the base in bf16) and the judge is Qwen3-14B, named as
\code{local:Qwen/Qwen3-14B@4096}. All models run locally.

\paragraph{Commands.}
The commands below are those the repository documents. The pilot-scale exams were run with
\code{splinter exam CANDIDATE --judge local:Qwen/Qwen3-14B@4096 --prompt "to think like Thomas
Jefferson" --json} without \code{--exam-set}, the form that examines a run's own held-out
records, at the revision of the time; the training runs with \code{splinter train
DIALOGUES VOICE --steps N --records-per-step 8} (the Adams run inside the one-sentence
\code{learn}).
\begin{small}
\begin{verbatim}
# materials for one person, and the pool an exam is reserved from
splinter-jefferson materials --resources RESOURCES --out ./materials
splinter-jefferson materials --exam-pool --resources RESOURCES --out ./pool
# the frozen anchor suite the release gate holds a candidate to
splinter eval --suite anchor --freeze samples/jefferson/anchor.jsonl \
  --freeze samples/adams/anchor-skills.jsonl
# one sentence, everything else autonomous
splinter "Learn to think like Thomas Jefferson based on the materials he has \
  written in directory ./materials"
# reserve and freeze an exam apart from any run (final test and dev suite)
splinter exam-set create ./pool --persona "Thomas Jefferson" \
  --families 50 --tasks-per-family 8 --dev-families 50 --dev-tasks-per-family 4 \
  --not-trained-by CANDIDATE
# size the exam by simulation, from an assumption or from a pilot report
splinter exam-set power --families 50 --tasks-per-family 8 --effect 0.10 \
  --replicates 4000
splinter exam-set power --from-report PILOT.json --families 39 --tasks-per-family 6
# train, keeping the adapter of every evaluation; choose a step on the dev suite
splinter train DIALOGUES VOICE --steps 120 --records-per-step 8 --eval-every 15 \
  --keep-evaluations
splinter select CANDIDATE --exam-set DEV --judge local:Qwen/Qwen3-14B@4096 [--adopt]
# the powered exam: base, prompted base, candidate, candidate under persona prompt
# (the reported pilots used --pilot-families 25 --no-voice; the full runs
# --no-voice without --pilot-families)
splinter exam CANDIDATE --exam-set EXAM --resamples 1 [--pilot-families 25] \
  [--no-voice] --judge local:Qwen/Qwen3-14B@4096 \
  --prompt "to think like Thomas Jefferson" --json
# a candidate asked alone (the reported deployed-arm pilots used --pilot-families 25
# --no-voice), to be paired offline with another report of the same exam
splinter exam CANDIDATE --exam-set EXAM --deployed-only ...
# analyses of a stored report; labels need a person
splinter exam-report labels-export REPORT --out LABELS --key KEY
splinter exam-report labels-import LABELS --key KEY
splinter exam-report memorisation REPORT --candidate CANDIDATE
splinter release CANDIDATE --judge local:Qwen/Qwen3-14B@4096
\end{verbatim}
\end{small}
Every job in this paper ran through a wrapper that pins one card and stops on any CPU
or software-adapter line, one job per card.

\paragraph{Building this paper.}
\code{make} regenerates every table and plot data file from \code{data/} and builds
\code{paper.pdf}. To update a result, edit its row in the file of its result under \code{data/} (\code{exams}, \code{anchor}, \code{training}, \code{pilot}, \code{deployed}, \code{full}, \code{full\_comparisons} or \code{power\_simulation}, each \code{.csv}); the script recomputes the exact sign tests and the
task-level bounds, refuses an exam row whose logged $p$ does not match the exact value, an
anchor row whose cells do not add up and a pilot row whose sign tests, Holm adjustment or
difference do not match its counts, a deployed-arm row whose sign tests, difference or
counts do not match, a full-run row whose sign tests, Holm adjustment, differences or outside-the-pilot counts do not
match its counts, and prints the pilot tables for completed rows. A pilot row
is produced from a run's report by \code{scripts/pilot\_row.py REPORT --arm NAME --description TEXT
--power P --power-fpr F}, which recomputes the counts from the report's per-task records and
refuses a report whose summary disagrees; $P$ and $F$ are the \code{planned} power and
false-positive rate of \code{splinter exam-set power --from-report REPORT --families 39
--tasks-per-family 6 --json}. A deployed-arm row is produced by \code{scripts/deployed\_row.py
REPORT --arm NAME --description TEXT --reference REPORT:ARM}, which pairs the report's
candidate under the persona prompt with the named arm of a four-arm report of the same exam by
task, recomputes every count, test and the family-clustered bootstrap interval (10,000
resamples, seed 1) from the per-task records, and refuses reports whose summaries disagree
with their records or whose judge versions differ. The rows of a full run are produced by
\code{scripts/full\_row.py REPORT --arm NAME --description TEXT --pilot-report REPORT}, which
appends to \code{data/full.csv} (the run, its judge, arms and the tasks outside the pilot) and
\code{data/full\_comparisons.csv} (the primary and five secondary comparisons), recomputes the
arm totals, discordant tasks, family wins and losses, length-matched tasks and exact sign tests
from the per-task records, refuses a report whose summary disagrees, and counts the pilot's
answers that the full run repeated word for word.
Every number in the tables was checked against the run's report by recomputing it; the run
reports themselves are not distributed with the paper, only the counts read from them.
