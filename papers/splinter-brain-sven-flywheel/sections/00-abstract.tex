\begin{abstract}
A local model can keep learning from a team's documents, tools and repositories only if the
path from a source to a released model can be inspected stage by stage. We describe a
self-learning loop built from three cooperating projects, Splinter (what is learned), Brain
(training and serving) and Sven (agents): a model proposes tasks that code admits or refuses
for named reasons, an agent attempts them, typed verifiers keep what they confirm, verified
experience becomes training data for a LoRA adapter, and the result is released only if four
checks over unseen material pass, with immutable releases and rollback. We state the
requirements that make such a loop work (independent held-out units, a retention check that
tests what was acquired, an anchor bound that counts net lost answers on a large enough suite,
a verifier that proves the tests ran, canaries in the gate), tie each to the code that
implements it or mark it planned, and report what the training substrate of one 95~GiB card
holds for a 27B model (bf16 LoRA and NF4 QLoRA qualified; a probe step at
\mThrNfFourEightOneNineTwoTokensPerS{} tokens/s, as measured). Every statement about the system
or a measurement carries an id in a claims ledger and is re-checked against the three
repositories at pinned commits or against a raw run record. Finally we register, before any run,
the experiment the loop exists for: whether a small model's adapter, trained on verified trajectories that a larger teacher
produced, raises completion of unseen repository tasks over the untrained small model, with
retention and a replication on a second, independent repository, and a follow-up in which the
larger model learns from its own verified trajectories. That claim is \emph{not yet measured}: this draft contains its protocol and replication recipe, the teacher's first pass, an underpowered pilot of the headline that does not show it, and the larger model's first training run, which its registered memorisation guard stopped before any evaluation.
\end{abstract}
