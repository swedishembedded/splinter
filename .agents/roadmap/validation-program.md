# Validation program: end-to-end conformance of Splinter against independent references

Scope: establish, with independent oracles, that Splinter selects valid tasks, records what the student did, builds the intended training data, supplies correct rewards and makes sound statistical and release decisions; leave a permanent, stronger test suite (phases 0-16, milestones M0-M8; this session CPU only).

## Boundaries

| Project | Owns the correctness of |
|---|---|
| Splinter | task selection, verification, data admission, dataset construction, scheduling, statistics, lineage, promotion |
| Sven | agent execution, tools, harnesses, authoritative trajectories |
| Brain | tokenization, inference, losses, gradients, optimizer updates, checkpoints, serving |

A Splinter test never certifies Brain's numerics or Sven's execution. A result names the revision and backend it was
measured on; a CPU result certifies no GPU path; a toy result certifies no generalisation. No backward compatibility
is kept: an incorrect or redundant implementation is deleted, not shimmed.

Acceptance states: `UNMAPPED -> SPECIFIED -> REFERENCE_PINNED -> GOLDEN_PASS -> ADVERSARIAL_PASS -> INTEGRATION_PASS ->
EMPIRICALLY_VALIDATED`; `CUSTOM_ORACLE_REQUIRED` where no external reference fits. A test that calls the production
function on both sides is not independent. Oracle strength, strongest first: exact derivation or enumeration,
independent reference implementation, established framework, metamorphic/property assertion, internal unit test.

Outcome classes kept distinct everywhere (admission, denominators, rewards, reports): `PASS`, `FAIL`, `UNGRADABLE`,
`INFRASTRUCTURE_ERROR`, `TIMEOUT`, `CONTAMINATED`, `UNSUPPORTED`.

## Layout

Extends, never parallels, `docs/contributing/validation.md`, `scripts/conformance/{evidence.py,mutants.py,mutants.tsv}`.

```
validation/
  references.lock.yaml        the oracle environment: every package at an exact version and wheel sha256, and
                              each reference's functions, conventions and confidence
  fixtures.yaml               every frozen fixture: its sha256, its oracle's sha256, references, consuming test
  fixtures/<area>/<name>.json frozen cases, reviewed, never regenerated by a test
  oracles/<area>/<name>.py    reference runners, run in target/validation/venv (never a Rust build dependency)
  capabilities.yaml           the inventory (Phase 0): one row per capability
  gaps.yaml                   the gap register: unverified -> confirmed | rejected -> fixed
crates/conformance/           splinter-conformance (dev-dependency): fixture loading checked against
                              fixtures.yaml, differential override (SPLINTER_FIXTURE_DIR), typed comparison
                              with tolerances reporting the first coordinate and the largest errors
scripts/conformance/
  external.py                 env (build the oracle venv from the lock, hashes required) | generate | check |
                              differential NAME --seed S (fresh draws through the same Rust test)
  test_external.py            the runner's own specification (10 refusals)
  evidence.py                 extended: each row records the fixtures, oracle digests and references it was held to
scripts/validation/
  baseline.py                 Phase 0 baseline runner (target/validation/baseline-results.json)
```

## Constraints of this session

- CPU only; no GPU workload (no `nvidia-smi` here). Phases 13-15 are recorded, not run.
- No hour-long suite: targets run one at a time under their own timeout (`scripts/validation/baseline.py`).
- Commits stay local; linear `main`; one self-contained commit per unit; gates never skipped.

## The first two waves (2026-11-23/24)

Defects found by the inventory, the baseline and the new adversarial specs, each fixed with a specification that
was seen to fail first, or rejected with its evidence (`validation/gaps.yaml` holds every one):

- decisions: a signed or unmeasured retention evaluation passed the release gate; a harness search crowned a
  useless candidate four times in ten; an intervention's bound used the normal quantile over four units; a
  samples arm's pass@k was any-of-fewer; a one-family interval read as zero-wide; an impossible exam plan was
  powered under another lead's name.
- controller: a panicking operation hung the run; a stage longer than ten minutes lost its lease; a crashed
  holder was judged by pid alone; a corrupted product or view was reused.
- data: an HTTP 499 endpoint was not a rejection; one bad metric emptied all; impossible log-probabilities and an
  empty prompt were labelled the policy's sample; a replaced system prompt kept its stale ids; a short duplicate
  escaped the leakage gate; an unreadable record became a free sample.
- security: a task repository could send any of the controller's variables to its own URL; a hub token went in
  clear to any host; an operator could read files its identity did not pin; a confined command reached any
  daemon's Unix socket (found by the new spec); a process budget that could not bind was recorded as binding;
  three credential-name rules disagreed; dead code held the weakest agent confinement.
- portability: HOME unset wrote state into the working directory; the integration tier never reached its
  mutants; the methods smokes and the package build failed on a machine unlike their author's.
- templates: the generations template could never promote (four paired attempts cannot reach the level).
- masks (6D, by enumeration of 1,113,876 projections): a premature reply that feedback answered was supervised as
  the final answer.
- untrusted input (16C, by property over damaged seeds): any message holding a letter whose lowercase is longer in
  UTF-8 crashed the parsers of what a person teaches; a truncated SAS transport file crashed its reader.
- recomputation (9C, each input of the reference recipe changed alone): a changed held-out task or evaluation
  environment reused the evaluation graded under the old one.
- crash safety (10B, the product store ended at each durability boundary): a view repaired after a crash mid-build
  left its half-built directory in the run for good.
- task kinds (4A, a kind never graded by less than it declares): a kind only a judge grades was answered where no
  judge is given, its attempts kept ungraded as if graded; a recall answer hedging among five candidates passed as
  stating the one fact.

- legacy pipelines (16D, by ablation): the CLI verbs that duplicated factory stages are deleted with the pipelines
  only they used (G-AS-11), the legacy exam seal whose reserved families nothing recorded (G-NEW-01) and the
  release path of the third lineage notion (G-FS-09); the stage ledger moved to its one user (G-FS-08).
