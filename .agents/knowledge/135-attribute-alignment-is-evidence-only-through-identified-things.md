# 135. Attribute alignment is evidence only through identified things, and a class is left alone

Aligning attribute phrases that no document uses together is sound for a thing with an identifier (`alder pump 3` has one set of attributes, so a phrase that replaces another across documents is a paraphrase) and unsound for a class (a client type has an open-ended set of situations; `the garbage rules change` and `a parking space is reassigned` are two situations that happen to be stated in different documents). Client-behaviour form, served embedder, seeds 7000-7004: with entity names left unaligned the attribute rule still merged 0, 1, 4, 4 and 8 pairs wrongly per corpus and had no true pair to find (the paraphrased type name differs from the original, so no key pair shares an entity), and selection with alignment scored 0.74 [0.59,0.90] against 0.78 [0.61,0.94] without, a paired -0.033 [-0.078, 0.000]. Aligning entities too had scored 0.40 against 0.52. Final rule: only statements about entities with a digit in the name are evidence. Behaviour: nothing is aligned, and on 5 fresh corpora (seeds 7100-7104) the aligned and unaligned runs are identical per corpus (difference 0.000 [0.000, 0.000]); property: aligned 0.94 [0.88,0.99] against unaligned 0.78 [0.68,0.88], paired +0.162 [0.058, 0.277] (on seeds 7000-7004: 0.97 against 0.67, +0.30 [0.13, 0.46]).

Rule: ship an alignment only with a rule that abstains where it cannot be checked; measure both forms on the same fresh corpora both ways. Supersedes the open question of finding 124. Evidence: splinter 973deb0d0, `crates/knowledge/src/goal/align.rs`, `~/project/shared/goal-selection/round4/`.
